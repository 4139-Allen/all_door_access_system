## 1. 项目概述

### 1.1 项目背景

传统门禁系统存在以下痛点：

- **管理分散**：设备、人员、权限各自为政，缺乏统一管理后台；
- **授权滞后**：人员变动后门禁权限调整依赖人工上门，无法远程实时授权；
- **管控缺失**：开门行为无记录、无审计，异常情况无法追溯；
- **体验单一**：只能在固定门禁终端操作，缺少移动化、智能化开门手段。

本系统构建一套**多端一体的门禁管控平台**，覆盖 Web 管理端、微信小程序、uni-app 移动 App，并与门禁硬件（STM32 控制板 + WiFi 模块）打通，实现远程授权、远程开门、行为审计与智能管控。

### 1.2 产品目标

1. **统一管控**：通过一个管理后台集中管理设备、用户、角色、权限与日志；
2. **远程授权**：支持远程绑定/解绑用户与设备、远程开门，突破物理距离限制；
3. **安全可控**：RBAC 细粒度权限、异常事件监控、设备锁定保护、全量操作审计；
4. **多端覆盖**：管理端（Web）、员工端（小程序 / App / Web）全场景覆盖；
5. **智能升级**：以自然语言指令（AI）驱动开门，为后续智能化能力奠定基础。

### 1.3 产品范围

**本期范围（基线）**：账号体系、用户与角色权限管理、设备管理与绑定、远程开门、开门日志、异常事件、数据统计、AI 智能开门、实时通知、多端（Web / 小程序 / App）与硬件（STM32 + WiFi + MQTT）联动。

**不纳入范围**：门禁硬件本身的机械结构、人脸/指纹生物识别算法自研、与第三方监控/安防平台对接（预留接口，后续规划）。

### 1.4 名词术语

| 术语 | 说明 |
|---|---|
| 设备（Device） | 一个门禁终端，由 STM32 控制板 + WiFi（ESP8266）组成，通过 MQTT 与后端通信 |
| 凭据 | 登录标识，支持手机号 / 邮箱 / 用户名三种形式 |
| 角色（Role） | 权限集合，系统内置 admin / operator / user，支持自定义角色 |
| 权限点（Permission） | 最小的操作授权单元，如 `door.open`、`device.edit` |
| 绑定（Bind） | 将用户与设备建立授权关系，被绑定用户可开该设备 |
| 设备锁定 | 设备端连续密码/指纹/刷卡错误 5 次后自动锁定，需管理端解锁 |
| 开门日志（DoorLog） | 每次开门操作的时间、设备、用户、结果快照记录 |
| 异常事件（Alert） | 设备锁定、开门失败等非正常事件 |
| 冷却时间 | 同一用户对同一设备两次远程开门的最小间隔（3 秒） |

## 2. 目标用户与使用场景

| 角色 | 用户 | 主要诉求 | 使用端 |
|---|---|---|---|
| 超级管理员 | 系统负责人/业主 | 全面管理设备、用户、角色权限、审计日志 | Web 管理后台 |
| 普通管理员 | 物业/部门主管 | 设备运维、用户授权、开门、查看全量日志与异常 | Web 管理后台 |
| 普通用户 | 员工/住户 | 查看可用设备、远程开门、查个人开门记录 | 小程序 / App / Web |
| 访客/临时人员 | 临时授权人员 | 通过临时账号开门（后续版本支持时效授权） | 小程序 / App |

典型场景：

- **场景 A（日常开门）**：员工在手机上打开小程序，查看已绑定设备，点击"开门"；设备 3 秒内响应，操作与结果记入日志。
- **场景 B（管理员远程授权）**：新员工入职，管理员在 Web 后台创建账号、分配角色、绑定对应门禁设备；离职时停用账号并解绑。
- **场景 C（异常处置）**：某设备因密码错误 5 次被锁定，管理员在 Web 收到异常事件通知并远程解除锁定。
- **场景 D（自然语言开门）**：管理员在 Web 仪表盘通过 AI 助手输入"打开会议室的门"，系统解析指令并执行。

## 4. 总体业务流程

### 4.1 远程开门流程（核心）

```
用户发起开门 ──► 身份鉴权(JWT) ──► 设备在线校验(MySQL+Redis)
      ──► 设备锁定校验(错误5次→拒绝) ──► 权限校验(admin/operator 或 已绑定)
      ──► 设备级分布式锁(防并发) ──► 3秒冷却校验
      ──► 下发 MQTT「OPEN_DOOR」命令 ──► 等待设备回复「OPENED」(最长5秒)
      ──► 成功：写日志(成功) + 清统计缓存 + WebSocket 通知管理员
      ──► 失败：写日志(失败原因) + 返回明确错误
```

### 4.2 登录流程

```
凭据输入 ──► 格式校验(手机号/邮箱/用户名 分类提示) ──► 查询账号
      ──► 账号不存在→"用户不存在" │ 停用→"账号已被停用" │ 密码错误→"密码错误"
      ──► 签发 JWT + Redis 登记 token ──► 前端存储并跳转
```

### 4.3 异常事件闭环

```
设备端密码/指纹/刷卡错误 ──► 连续错误5次 ──► 设备锁定(Redis 锁+TTL)
      ──► 产生异常事件 ──► 管理端查看/统计 ──► 管理员解除锁定 ──► 设备恢复
```

## 5. 角色与权限模型

### 5.1 内置角色

| 角色代码 | 名称 | 定位 | 是否系统内置 |
|---|---|---|---|
| admin | 超级管理员 | 全部权限 | ✅（不可改权限、不可删除） |
| operator | 普通管理员 | 设备运维 + 日志 + 异常处置 | ✅ |
| user | 普通用户 | 个人开门 + 个人日志 | ✅ |

支持创建**自定义角色**并分配权限点（`role_code` 全局唯一且创建后不可修改；超级管理员角色的权限不可修改）。

### 5.2 权限点清单

| 权限代码 | 权限名称 | 模块 | admin | operator | user |
|---|---|---|---|---|---|
| `dashboard.view` | 查看仪表盘 | 仪表盘 | ✅ | ✅ | — |
| `door.open` | 远程开门 | 门禁控制 | ✅ | ✅ | ✅ |
| `door.view_own_log` | 查看个人开门记录 | 门禁控制 | ✅ | ✅ | ✅ |
| `device.view` | 查看设备列表 | 设备管理 | ✅ | ✅ | — |
| `device.create` | 创建设备 | 设备管理 | ✅ | ✅ | — |
| `device.edit` | 编辑设备 | 设备管理 | ✅ | ✅ | — |
| `device.delete` | 删除设备 | 设备管理 | ✅ | ✅ | — |
| `device.bind` | 绑定/解绑用户 | 设备管理 | ✅ | ✅ | — |
| `log.view` | 查看全部开门记录 | 日志管理 | ✅ | ✅ | — |
| `log.export` | 导出日志 | 日志管理 | ✅ | ✅ | — |
| `alert.view` | 查看异常事件 | 异常事件 | ✅ | ✅ | — |
| `alert.unlock` | 解除设备锁定 | 异常事件 | ✅ | ✅ | — |
| `user.view` | 查看用户列表 | 用户管理 | ✅ | — | — |
| `user.manage` | 管理用户 | 用户管理 | ✅ | — | — |

> 权限说明：拥有 `device.view` 的用户可操作任意设备（管理员）；普通用户仅能操作已绑定设备。

### 5.3 权限控制机制

- 后端接口通过 `RequirePermission("perm.code")` 依赖注入进行鉴权，与用户角色无关、与权限点绑定；
- 用户权限 = 角色权限集合，查询结果经 Redis 缓存（变更时失效）；
- 前端根据登录返回的 `permissions` 数组控制菜单与按钮显隐（仅控制展示，真实鉴权在后端）。

## 6. 功能需求

> 优先级说明：**P0** = 上线必备；**P1** = 重要，发布后尽快补齐；**P2** = 增强体验。

### 6.1 账号体系与认证（P0）

| 功能 | 描述 |
|---|---|
| F-AUTH-01 统一密码登录 | 支持手机号/邮箱/用户名 + 密码登录；凭据按类型校验并返回针对性错误（用户不存在/密码错误/账号已停用/未设置密码） |
| F-AUTH-02 验证码登录 | 手机号/邮箱 + 短信/邮箱验证码登录；未注册手机号/邮箱自动注册；用户名不支持验证码登录 |
| F-AUTH-03 发送验证码 | 自动识别手机号/邮箱并发送验证码，60 秒倒计时 |
| F-AUTH-04 用户注册 | 用户名 + 密码注册普通用户；用户名规则：字母/数字/下划线/点/中划线/中文，1–32 位 |
| F-AUTH-05 退出登录 | 注销当前 token 并加入黑名单，立即失效 |
| F-AUTH-06 修改密码 | 校验原密码后修改；成功后当前用户全部 token 失效 |
| F-AUTH-07 重置密码 | 手机号 + 验证码重置密码；成功后该用户全部 token 失效 |
| F-AUTH-08 微信小程序登录 | wx.login code 换取 JWT；新用户自动注册（openid 派生用户名） |
| F-AUTH-09 微信绑定 | 将已有账号绑定到微信登录用户（校验用户名+密码） |
| F-AUTH-10 登录风控 | 同一 IP 5 次/60 秒频率限制；密码模式附带数学验证码 |

**验收标准（F-AUTH-01）**
- Given 输入不存在的账号，When 提交登录，Then 返回 400 且提示"用户不存在"；
- Given 输入已停用账号，Then 提示"账号已被停用"；
- Given 密码错误，Then 提示"密码错误"，且不暴露账号信息之外的多余信息；
- Given 输入含非法字符的凭据，Then 返回 422 且按类型提示（邮箱格式不正确 / 手机号格式不正确 / 用户名规则）；
- Given 连续同一 IP 失败 5 次，Then 第 6 次起返回 429 频率限制提示。

### 6.2 用户管理（P0，admin）

| 功能 | 描述 |
|---|---|
| F-USER-01 用户列表 | 分页查询，支持按用户名/角色筛选 |
| F-USER-02 创建用户 | 指定用户名/密码/角色；重复用户名拒绝 |
| F-USER-03 用户导入 | 批量导入用户（CSV），逐行返回成功/失败原因 |
| F-USER-04 修改角色 | 变更用户角色 |
| F-USER-05 停用/启用用户 | 软删除（用户名改 `已停用_{id}_{原名}` 释放），停用后 token 失效 |
| F-USER-06 查看绑定设备 | 查看某用户绑定的设备（完整设备对象） |
| F-USER-07 修改用户名 | 校验唯一性后更新 |
| F-USER-08 绑定手机/邮箱 | 需验证码，唯一性校验，支持解绑 |

**验收标准（F-USER-05）**
- Given 停用一个在线用户，When 其携带旧 token 调用接口，Then 立即 401；
- Given 删除后，Then 该用户名可被重新注册，日志中历史记录仍可追溯。

### 6.3 角色与权限管理（P0，admin）

| 功能 | 描述 |
|---|---|
| F-RBAC-01 权限列表 | 按模块分组展示全部权限点 |
| F-RBAC-02 角色列表 | 展示全部角色及其权限 |
| F-RBAC-03 创建角色 | 自定义角色（name + 唯一 role_code） |
| F-RBAC-04 修改角色 | 仅可改名称，role_code 创建后不可修改；拒绝多余字段 |
| F-RBAC-05 删除角色 | 删除非系统角色（被引用时的约束见验收） |
| F-RBAC-06 设置角色权限 | 全量替换角色的权限集合；超级管理员角色权限不可修改 |

**验收标准（F-RBAC-06）**
- Given 修改某自定义角色权限，When 保存，Then 权限全量替换且该角色下所有用户权限缓存失效；
- Given 对 admin 角色设置权限，Then 拒绝并提示"超级管理员角色的权限不可修改"。

### 6.4 设备管理（P0，admin）

| 功能 | 描述 |
|---|---|
| F-DEV-01 创建设备 | 指定设备名（如 001）、位置；名称唯一 |
| F-DEV-02 设备列表 | 按名称模糊查询；管理员看全部，普通用户看已绑定设备（含 Redis 60s 缓存） |
| F-DEV-03 编辑设备 | 修改名称/位置 |
| F-DEV-04 删除设备 | 需先解绑全部用户，否则拒绝 |
| F-DEV-05 在线状态 | 设备在线状态由 MQTT 心跳驱动，实时写 Redis，延迟同步 MySQL |

**验收标准（F-DEV-04）**
- Given 设备仍有绑定用户，When 删除，Then 拒绝并提示先解绑；
- Given 删除后，Then 设备列表、日志、统计缓存全部失效刷新。

### 6.5 设备绑定（P0，admin）

| 功能 | 描述 |
|---|---|
| F-BIND-01 绑定用户 | 将用户绑定到设备（多对多） |
| F-BIND-02 解绑用户 | 从设备移除用户授权 |
| F-BIND-03 绑定管理页 | 双栏页面：左侧已绑定（可解绑），右侧全部设备（可绑定，已绑置灰） |

**验收标准（F-BIND-01）**
- Given 绑定完成后，When 该用户登录，Then 设备列表可见该设备并可开门；
- When 解绑，Then 该用户立即无法对该设备开门（无权限提示）。

### 6.6 门禁控制（P0）

| 功能 | 描述 |
|---|---|
| F-DOOR-01 远程开门 | 见 4.1 开门流程；含在线校验、锁定校验、权限校验、分布式锁、冷却、MQTT 命令与设备确认、超时处理 |
| F-DOOR-02 个人开门记录 | 当前用户的开/关记录，分页查询 |

**验收标准（F-DOOR-01）**
- Given 设备在线且用户已绑定，When 点击开门，Then 5 秒内返回"开门成功"并生成成功日志，管理员实时收到通知；
- Given 设备离线，Then 提示"设备不在线"并记录失败日志；
- Given 设备已锁定，Then 提示剩余锁定时长；
- Given 未绑定且无 `device.view` 权限，Then 提示无权限并记录失败日志；
- Given 3 秒内重复开门，Then 提示操作过于频繁；
- Given 设备 5 秒无响应，Then 提示设备无响应，记录失败日志。

### 6.7 开门日志（P0）

| 功能 | 描述 |
|---|---|
| F-LOG-01 全量日志 | 管理员查看全量日志，支持按用户/设备/状态/时间范围筛选、分页 |
| F-LOG-02 日志导出 | 按当前筛选条件导出，单次上限 10000 行（防超限） |
| F-LOG-03 快照追溯 | 日志存设备名/位置/用户名快照，设备或用户被删后日志仍可读 |

**验收标准（F-LOG-01）**
- Given 按时间范围查询，Then 走 `time` 索引，返回该区间记录；
- Given 用户被停用后，Then 历史日志显示"原用户名（已停用_id）"，不丢记录。

### 6.8 异常事件（P1，admin）

| 功能 | 描述 |
|---|---|
| F-ALERT-01 异常事件列表 | 设备锁定、开门失败等事件，按设备/类型/时间筛选、分页 |
| F-ALERT-02 异常统计 | 指定时间范围（默认 24h，最大 720h）内异常事件统计 |
| F-ALERT-03 解除设备锁定 | 管理员一键解除指定设备的密码锁定 |

**验收标准（F-ALERT-03）**
- Given 设备处于锁定态，When 管理员解除锁定，Then 设备恢复可开门，锁定 Redis 键删除。

### 6.9 数据统计 / 仪表盘（P1，admin）

| 功能 | 描述 |
|---|---|
| F-STAT-01 总览统计 | 关键指标（开门次数、设备数、用户数等），按角色返回数据范围（admin 全量 / user 个人） |
| F-STAT-02 本周趋势 | 本周开锁趋势曲线 |
| F-STAT-03 开锁方式占比 | 按开锁方式（远程开门/MQTT 密码开门等）聚合分布 |

**验收标准（F-STAT-01）**
- Given admin 查看，Then 显示全量统计；Given 普通用户查看，Then 仅显示其个人相关数据（权限不足返回 403 或按角色降级）。

### 6.10 AI 智能开门（P1，admin/具备权限者）

| 功能 | 描述 |
|---|---|
| F-AI-01 自然语言指令 | 通过自然语言（如"打开会议室的门"）识别设备名并执行开门 |
| F-AI-02 上下文记忆 | 15 分钟内对话上下文缓存在 Redis，支持多轮指令 |
| F-AI-03 授权控制 | 需 `door.open` 或 `device.view` 权限 |
| F-AI-04 容错 | 未配置 DeepSeek Key 时系统正常运行，仅 AI 功能不可用 |

**验收标准（F-AI-01）**
- Given 输入"打开大门"，When 提交，Then 自动匹配设备并开门，返回结果；
- Given 无法识别设备名，Then 返回明确提示且不执行任何开门动作。

### 6.11 实时通知（P1，admin）

| 功能 | 描述 |
|---|---|
| F-WS-01 WebSocket 连接 | 管理员连接 `ws://host/ws`，JWT 鉴权 |
| F-WS-02 开门实时推送 | 任意用户开门成功/失败时向在线管理员实时推送事件 |

**验收标准（F-WS-01）**
- Given 管理端登录，Then WebSocket 建立并保持心跳；
- Given 任意用户开门，Then 在线管理员在 1 秒内收到通知。

### 6.12 个人中心 / 资料（P2）

| 功能 | 描述 |
|---|---|
| F-PROFILE-01 查看/修改资料 | 用户名、头像、手机号、邮箱、角色展示 |
| F-PROFILE-02 头像上传 | 支持 JPG/PNG/GIF/WebP，≤1MB；nginx `client_max_body_size` 已适配，超限返回 JSON 400 |

### 6.13 多端兼容（P1）

| 功能 | 描述 |
|---|---|
| F-MP-01 小程序 | 微信一键登录 + 账号密码登录；门禁列表下拉刷新；个人日志分页；个人中心改密/退出 |
| F-MP-02 移动 App | uni-app 跨端（iOS/Android/H5），登录、开门、日志、改密、设备绑定管理 |
| F-MP-03 统一鉴权 | 三端均使用 JWT（Web 走 `Authorization: Bearer`，小程序/App 走 `X-Token`） |

### 6.14 硬件与通信（P0，配套）

| 功能 | 描述 |

| F-HW-05 状态上报 | 设备心跳驱动在线状态实时刷新 |

## 7. 非功能需求

### 7.1 性能

| 指标 | 要求 |
|---|---|
| 接口响应 | 常规查询 P95 < 500ms；开门命令端到端（含设备回复）≤ 5s |
| 并发 | 支持 100+ 并发在线用户；开门接口设备级互斥，防并发误开 |
| 缓存命中 | 设备列表、统计、权限、AI 上下文均走 Redis 缓存并按时效失效 |
| 日志量 | 单次日志导出上限 10000 行，防止大表全量导出拖垮数据库 |

### 7.2 安全

| 类别 | 要求 |
|---|---|
| 认证 | JWT + Redis token 登记与黑名单；改密/重置密码/停用后旧 token 立即失效 |
| 口令 | bcrypt 哈希（72 字节上限）；密码 6–20 位强约束 |
| 风控 | 登录频率限制 5 次/60s/IP；密码登录附带数学验证码 |
| 越权防护 | 后端 `RequirePermission` 统一鉴权；前端隐藏不等于安全，仅作展示 |
| 注入 | 全程 SQLAlchemy ORM 参数化，防 SQL 注入 |
| 输入校验 | Pydantic 全量校验 + 统一 422 中文提示；拒绝多余字段 |
| 传输 | 生产环境强制 HTTPS（Nginx + SSL）；CORS 白名单收敛 |
| 密钥 | `SECRET_KEY` ≥32 字符；Redis 生产环境启用密码 |

### 7.3 可靠性与可用性

- 开门命令带设备确认机制，超时明确报错，避免"假成功"；
- 设备级分布式锁（Redis `SET NX EX`，值校验释放），防误删他人锁；
- 日志/统计/异常缓存变更即时失效，保证数据一致；
- 30 天日志轮转，磁盘可控；
- AI 依赖缺失不阻塞系统主流程。

### 7.4 兼容性

- Web：Chrome / Edge 等现代浏览器（Vue3 + Element Plus）；
- 小程序：微信基础库兼容版本；
- App：iOS / Android / H5 三端（uni-app）；
- 后端：Python 3.13 + FastAPI，Docker 容器化部署。

### 7.5 可维护性

- 三层架构（API / Service / Model），服务层统一异常转 `{code,msg,data}`；
- 结构化日志（支持 JSON 格式），按天切分、可对接 ELK/Loki/云 SLS；
- 数据库迁移走 Alembic，全量变更需走迁移脚本；
- 自动化测试：接口自动化（Pytest + Allure）覆盖核心业务链路。

## 8. 数据需求

### 8.1 核心数据模型

| 模型 | 关键字段 | 说明 |
|---|---|---|
| User | username(唯一)、password(bcrypt)、role、is_active、is_builtin、phone、email、avatar | 账号 |
| Device | name(唯一)、status(online/offline)、location | 门禁设备 |
| UserDevice | user_id、device_id（级联删除） | 用户-设备绑定 |
| DoorLog | device_name/location/user_name(快照)、action、status、ip、time | 开门日志，time/action 建索引 |
| Role | name、role_code(唯一)、is_system | 角色 |
| Permission | perm_code(唯一)、name、module | 权限点 |
| RolePermission | role_id、permission_id | 角色-权限 |

### 8.2 缓存设计

| 缓存键 | 内容 | TTL |
|---|---|---|
| `token:{token}` | 有效会话 | token 有效期 |
| `blacklist:{token}` | 已注销 token | 24h |
| `cache:device:list:user:{id}` | 用户设备列表 | 60s |
| `stat:user:{id}` | 用户统计 | 180s |
| `ai:context:user:{id}` | AI 对话上下文 | 900s |
| `door:lock:{device_id}` | 设备分布式锁 | 5s |
| `door:cooldown:{uid}:{devid}` | 开门冷却 | 3s |
| `door:err:lock:{device}` | 设备锁定标记 | 按锁定时长 |
| `device:online:{name}` | 设备实时在线 | 心跳维护 |

### 8.3 数据一致性

- 设备在线状态以 Redis 为准（实时），延迟同步 MySQL；
- 日志/统计/异常事件缓存按写操作即时失效；
- 用户权限缓存随角色权限变更全量失效。

## 10. 安全与合规

- **数据合规**：涉及手机号、邮箱等个人信息，遵循《个人信息保护法》，仅用于登录与通知，支持解绑；日志含操作 IP，供审计。
- **审计**：开门/改密/权限变更等敏感操作全量留痕，异常事件可追溯。
- **发布安全**：`.env` 不入库；默认管理员密码首登修改；`ALLOWED_ORIGINS` 生产收敛。
- **备份**：MySQL 定期备份；日志按天留存 30 天。

## 13. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 设备离线/网络抖动 | 开门失败 | MQTT 心跳 + Redis 实时在线判定 + 明确超时提示；失败留痕 |
| 密码暴力破解 | 设备/账号被锁 | 登录限流 + 验证码；设备错误 5 次锁定 + 管理端解锁 |
| 多端并发开门 | 门状态不一致 | 设备级分布式锁 + 冷却时间 |
| 数据库/缓存不一致 | 展示错误 | Redis 为准的实时状态 + 写后失效策略 |
| AI 依赖异常 | 智能功能不可用 | 依赖隔离，不阻塞主流程 |
